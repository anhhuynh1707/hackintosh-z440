# HP Z440 Hackintosh · macOS Sequoia

macOS Sequoia 15.8.2 boots on this HP Z440 with an RTX 3050 using OpenCore and the community NullMoth NVIDIA driver, now upgraded to **2.8**. In earlier tests at 1080p, window transitions and desktop animations felt smooth enough for everyday use. Onboard sound, including the internal speaker, and reliable sleep and wake are still open. Windows reached an 8 GiB BAR1 on the same card. The last verified macOS BAR1 readback was 64 MiB.

## Tested hardware and software

| Component | Tested configuration |
| --- | --- |
| Workstation | HP Z440, board 212B |
| CPU and memory | Intel Xeon E5-1603 v4 at 2.8 GHz, 4 cores, 8 GB DDR4-2133 |
| GPU | MSI GeForce RTX 3050 6 GB (GA107, PCI ID `10de:2584`) |
| Display | Dell P2217H, 1920 × 1080 at 60 Hz |
| Firmware | HP M60 family. The original Windows inventory shows v02.58. The later ReBAR setup used a modified M60 02.62 BIOS region. |
| Wireless | TP-Link TX55 with MediaTek MT7922 (`14c3:7922`) |
| macOS | Sequoia 15.8.2, build `24H232` |
| Bootloader | OpenCore 1.0.9 release build with OpenCanopy, booted from the USB named `1401`. The Mac model identifier is `MacPro7,1`. The EFI has the Broadwell-E CPUID override for Xeon v4. |
| NVIDIA driver | NullMoth 2.8 installed. The last verified desktop and BAR1 results were recorded on 2.7.2. |

## What worked

| Feature | What we verified |
| --- | --- |
| Boot and desktop | The adapted OpenCore EFI reached the existing Sequoia installation and a usable desktop. |
| Graphics | NullMoth's NVIDIA extensions loaded. System Information reported the RTX 3050, all 6 GB of VRAM, Metal 3, and the Dell display at 1080p/60 Hz. Desktop animation was usable in practice. |
| Wired Ethernet | We connected to the Z440 over Ethernet and collected diagnostics by SSH. |
| USB boot and mapping | The boot USB mounted in macOS. USBToolBox loaded, and we verified that the machine-specific USB map survived the EFI migration. We still need to check every physical port individually. |
| Resizable BAR in Windows | GPU-Z reported ReBAR enabled and BAR1 at 8192 MiB. [Windows GPU-Z screenshot](enable-resize-bar-z440_win.png) |

## What remains

| Feature | Status |
| --- | --- |
| Onboard audio and internal speaker | Core Audio showed no devices and macOS did not report a codec vendor ID. The AppleALC layout 15 setup and a local controller patch did not produce audible sound. The internal speaker, analog jacks and microphone still need verification. |
| Sleep and wake | Reliable sleep and resume remain unresolved. |
| BAR1 in macOS | The last saved macOS BAR readback was **64 MiB**. BAR1 is the window through which the CPU accesses GPU memory. The card still has **6 GB of VRAM**. The small window limits some graphics allocations. We verified ordinary desktop use on one 1080p display. |
| Wi-Fi and Bluetooth | The experimental MediaTek extensions loaded on an earlier boot. The EFI retains the app-managed Wi-Fi setup. Native Wi-Fi, Bluetooth, AirDrop, and long-term wireless stability remain unverified on this machine. |

## How we got here

1. **Prepared the Windows and firmware baseline.** We kept a BIOS backup and worked with the community ReBAR-only M60 02.62 BIOS region. The Windows-side tools in the project are Intel Flash Programming Tool and ReBarUEFI's `ReBarState.exe`. On the tested machine, HP's **Advanced → Performance Options → MMIO Assignment Mode** was set to **64 Bit**. GPU-Z confirmed UEFI boot, Above 4G Decoding, CSM disabled, and an 8 GiB BAR1. Treat the files under `WIN64/` as artifacts from this machine. Flashing a BIOS image requires verifying the exact board and image and having a recovery path. [HP Z440 technical guide](https://h30434.www3.hp.com/psg/attachments/psg/Business-PC-Workstation-POS/58456/1/HP%20Z440%20Workstation%20Technical%20Guide.pdf) · [ReBarUEFI and ReBarState 0.3](https://github.com/xCuri0/ReBarUEFI/releases/tag/0.3) · [Z440 Above 4G discussion](https://github.com/xCuri0/ReBarUEFI/issues/91) · [Community Z440 procedure with the matching firmware filename](https://www.reddit.com/r/homelab/comments/1wlio91/resizable_bar_officially_working_on_hpz440_with/)
2. **Booted the macOS installer from USB.** The 1401 USB has OpenCore under `EFI/` and the Apple recovery image and chunklist under `com.apple.recovery.boot/`. Boot the USB in UEFI mode, pick macOS Recovery in OpenCore, use wired Ethernet for Recovery, and install to the intended APFS target. For installer restarts, boot through the same USB and select the installer entry until the installed macOS volume is ready. The repo's [EFI folder](EFI/) contains the boot files. Recovery media comes from Apple. [1401 installer project](https://github.com/nullmoth/1401) · [Dortania installer guide](https://dortania.github.io/OpenCore-Install-Guide/installer-guide/) · [Dortania HEDT configuration guide](https://dortania.github.io/OpenCore-Install-Guide/config-HEDT/haswell-e.html)
3. **Installed the NVIDIA driver inside macOS.** The USB originally carried the 1401 Mac companion and the NullMoth 2.6.6 package. We tested later packages and verified **2.7.2** with `NVRM`, `NVRMFB`, `NVAccel`, and `NVRMAGDC` loaded. We later upgraded to **2.8**. The driver lives in macOS, while the EFI supplies its boot arguments, Lilu, AMFIPass and the required reduced security settings. The current picker also has options to boot once without the driver or request its removal at the next start. [NullMoth 2.8 release](https://github.com/nullmoth/nvidia-macos-driver/releases/tag/v2.8) · [NullMoth 2.7.2 release](https://github.com/nullmoth/nvidia-macos-driver/releases/tag/v2.7.2) · [OpenCore integration and recovery instructions](https://github.com/nullmoth/nvidia-macos-driver#wiring-into-an-existing-opencore-setup)
4. **Migrated to the OpCore Simplify EFI.** We moved from a debug build and text picker to OpenCore 1.0.9 release with OpenCanopy. We carried over the existing `MacPro7,1` identity and measured `UTBMap.kext`, dropped the generic USB map, and kept `XhciPortLimit` off. We corrected the SMBus ACPI table from `PCI0.SBUS` to `PCI0.SMBS` and retained the EC, PLUG, RTC0, UNC and USBX tables. We left the MediaTek device visible, kept `SimpleMtkWlan.kext` and `itlmt7922.kext` 0.2.2 for Sequoia, and left WhateverGreen out of this configuration. The driver already installed in macOS stayed in place during the migration. [OpenCorePkg](https://github.com/acidanthera/OpenCorePkg) · [OpCore Simplify NVIDIA integration](https://github.com/lzhoang2801/OpCore-Simplify/commit/8df623a89acf9861d09a32b085617d232b22be1a) · [USBToolBox](https://github.com/USBToolBox/tool) · [USBToolBox kext](https://github.com/USBToolBox/kext) · [SimpleMtkWlan](https://github.com/laobamac/SimpleMtkWlan) · [MT7922 driver and ItlWiFi7922 app](https://github.com/hbyonly1/itlmt7922-wifi)
5. **Kept the bootable 64 MiB configuration after larger BAR tests.** With `Booter → Quirks → ResizeAppleGpuBars = 0` and `UEFI → Quirks → ResizeGpuBars = -1`, OpenCore reduces BAR1 for the Apple boot path. NullMoth tried placing an 8 GiB window at 56 TiB, macOS could not map it, and the driver restored the smaller assignment. The 128 MiB trial failed to reach a usable boot. Leaving the 8 GiB size in place at handoff produced a black screen while SSH still worked, so we restored the working EFI. The firmware menu investigation and a locally built NVRM candidate also left the 8 GiB goal open. [OpenCore configuration reference](https://github.com/acidanthera/OpenCorePkg/blob/master/Docs/Configuration.tex) · [NullMoth issue #320](https://github.com/nullmoth/nvidia-macos-driver/issues/320) · [BAR placement preflight PR #431](https://github.com/nullmoth/nvidia-macos-driver/pull/431) · [Address-limit PR #473](https://github.com/nullmoth/nvidia-macos-driver/pull/473)

## Audio investigation

The onboard Intel HDA controller (`8086:8d20`) appeared in PCI diagnostics, but macOS had no usable codec or sound devices. We tried AppleALC configurations with layouts 11 and 15. The current EFI has AppleALC 1.9.9 and layout 15. The OpenCore patch for AppleHDAController 600.2 reported `Not Found` at boot. A local Lilu plugin also failed to apply its patch and was rolled back.

The HP Zx40 guide added during follow-up reports working analog audio and an internal speaker on a **Z640 running Sonoma with a Radeon RX 580**. Its EFI uses an SSDT-HPET and interrupt-resource patches. BillDH2k’s related project lists AppleALC layout 11 and a similar HPET fix and reports testing on Sequoia 15.5. The current Z440 EFI has neither an SSDT-HPET nor ACPI patch entries. Our saved DSDT contains the HPET, timer IRQ 0 and RTC IRQ 8 resources, so an HPET test built for this firmware is a candidate. We still need a fresh codec readback and a listening test. [HJebbour's HP Zx40 guide](https://www.insanelymac.com/forum/topic/359545-guide-macos-on-hp-z640z440z840-haswell-ebroadwell-e/) · [HJebbour's reference EFI](https://github.com/HJebbour/HP-Z640-Hackintosh) · [BillDH2k's Z440/Z640/Z840 EFI](https://github.com/BillDH2k/Hackintosh-HP-Z440-Z640-Z840-OpenCore) · [AppleALC supported codecs](https://github.com/acidanthera/AppleALC/wiki/Supported-codecs) · [Dortania HPET/IRQ guide](https://dortania.github.io/Getting-Started-With-ACPI/Universal/irq.html)
